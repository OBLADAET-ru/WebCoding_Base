База знаний WEBCODE

Структурированный справочник по веб-разработке. От верстки и дизайна до серверов и безопасности.

0.1

Что это за проект?

WEBCODE x ART — это открытый учебник и база знаний для веб-разработчиков, дизайнеров и всех, кто хочет создавать современные сайты и веб-приложения. Здесь вы найдете всю необходимую теорию и практику: от того, как работает браузер и HTML, до настройки серверов, баз данных и деплоя проектов.

Мы не привязываемся к одному языку или фреймворку. В базе собраны лучшие практики Frontend и Backend разработки, современные подходы к дизайну (UI/UX) и работе с кодом. Это не просто статьи, а руководство к действию.

0.2

Для кого этот сайт?

  • Для начинающих (Junior): чтобы понять, как устроен веб, выучить HTML, CSS и JavaScript, научиться верстать адаптивные сайты и не бояться серверной части.
  • Для дизайнеров: чтобы понять, как их макеты превращаются в код, как работает сетка, отступы, типографика и адаптивность.
  • Для Middle-разработчиков: чтобы углубить знания в архитектуре приложений, базах данных, API и настройке CI/CD.
  • Для всех, кто готовится к собеседованию: чтобы освежить в памяти ключевые термины, паттерны и ответы на частые вопросы.

Главная / §1 Основы

§1. Как работает интернет и веб

Базовые принципы, без которых не начнется разработка

1.1

Клиент-серверная архитектура

Веб построен на модели «Клиент-Сервер». Клиент — это ваш браузер (Chrome, Safari), который отправляет запросы. Сервер — это мощный компьютер, который хранит файлы сайта и базы данных, обрабатывает запрос и возвращает ответ (HTML-страницу, картинку или JSON с данными). Браузер, получив ответ, интерпретирует его и отрисовывает страницу на экране.

Важно понимать, что сервер не отправляет вам готовую картинку сайта. Он отправляет код (HTML, CSS, JS), а браузер уже самостоятельно собирает из него визуальную страницу. Этот процесс называется рендерингом.

ℹ️
Важно: Когда вы вводите адрес сайта в браузер, он отправляет HTTP-запрос на сервер. Сервер отвечает статус-кодом (например, 200 OK или 404 Not Found) и контентом.
1.2

Что такое DNS и домены

Люди запоминают слова (например, `google.com`), а компьютеры — числа (IP-адреса, например `142.250.190.46`). DNS (Domain Name System) — это телефонная книга интернета, которая переводит понятные доменные имена в IP-адреса серверов.

Когда вы вводите домен, ваш компьютер сначала обращается к DNS-серверу, чтобы узнать IP-адрес, а затем отправляет запрос уже на этот IP. Этот процесс занимает миллисекунды, но именно он позволяет интернету работать так, как мы привыкли.

1.3

HTTP и HTTPS

HTTP (HyperText Transfer Protocol) — это язык общения между клиентом и сервером. Именно через него передаются все данные в вебе. Однако обычный HTTP передает данные в открытом виде. HTTPS — это тот же протокол, но с шифрованием (SSL/TLS). Современные браузеры помечают сайты без HTTPS как «небезопасные».

Главная / §2 HTML & CSS

§2. HTML и CSS

Язык разметки и язык стилей — фундамент любого сайта

2.1

Семантический HTML

HTML (HyperText Markup Language) отвечает за структуру страницы. Важно использовать семантические теги (header, main, footer, article, nav), а не только div. Это помогает поисковым системам (SEO) и скринридерам для людей с ограниченными возможностями понимать, что находится на странице.

<header>
    <nav>
        <a href="/">Главная</a>
    </nav>
</header>
2.2

Flexbox и CSS Grid

Раньше верстка была болью (таблицы, float). Сейчас есть мощные инструменты для создания раскладок:
Flexbox — идеален для выравнивания элементов в одном направлении (например, меню в строку или карточки в ряд). Он отлично справляется с динамическим контентом.
CSS Grid — идеален для сложных двумерных сеток (например, раскладка «шапка, две колонки и подвал»). Позволяет задавать точные размеры ячеек.

/* Центрирование через Flexbox */
.container {
    display: flex;
    justify-content: center;
    align-items: center;
}
2.3

Box Model (Блочная модель)

Каждый элемент на странице — это прямоугольник, состоящий из четырех слоев: content (контент), padding (внутренний отступ), border (рамка) и margin (внешний отступ). Понимание этой модели критично для правильного позиционирования элементов.

Главная / §3 JavaScript

§3. JavaScript

Язык, который оживляет сайты

3.1

DOM (Document Object Model)

Когда браузер загружает HTML, он строит дерево DOM. JavaScript может обращаться к этому дереву, менять стили, добавлять или удалять элементы. Именно так работают все интерактивные элементы: выпадающие меню, слайдеры, модальные окна.

3.2

Асинхронность (Fetch и Promise)

JavaScript однопоточный, но ему нужно общаться с сервером (загружать данные без перезагрузки страницы). Для этого используются Promise и async/await. Запросы к серверу (API) делаются через метод `fetch`. Это позволяет обновлять контент на странице без её полной перезагрузки.

async function getUsers() {
    const response = await fetch('https://api.example.com/users');
    const users = await response.json();
    console.log(users);
}
3.3

ES6+ (Современный синтаксис)

Современный JS сильно отличается от того, что было 10 лет назад. Обязательно к изучению: стрелочные функции (`() => {}`), деструктуризация (`const { name } = user`), шаблонные строки (`` `Привет, ${name}` ``) и модули (`import/export`).

Главная / §4 Фреймворки

§4. Фронтенд-фреймворки

React, Vue, Angular

4.1

Зачем нужны фреймворки?

На чистом JavaScript становится тяжело писать большие приложения (например, соцсети или админки). Фреймворки (React, Vue) позволяют разбивать интерфейс на переиспользуемые компоненты и автоматически обновлять DOM при изменении данных (State). Это делает код более предсказуемым и легким в поддержке.

4.2

React

Самый популярный фреймворк от Facebook. Использует JSX (смесь HTML и JS) и Virtual DOM для высокой производительности. Если вы знаете React, вы легко найдете работу.

4.3

Vue.js

Более простой в изучении фреймворк. Отлично подходит для быстрого старта и интеграции в существующие проекты. Использует декларативный рендеринг и реактивность из коробки.

Главная / §5 Backend

§5. Языки серверной разработки

Что работает «под капотом» сайта

5.1

Node.js

Позволяет писать серверный код на JavaScript. Идеально, если вы фронтендер и хотите стать Fullstack-разработчиком. Использует асинхронную модель, отлично справляется с большим количеством одновременных запросов (например, в чатах).

5.2

Python (Django / FastAPI)

Отличный выбор для сложной бизнес-логики, работы с данными и машинного обучения. Django дает «все из коробки» (админку, ORM), а FastAPI — максимальную скорость и простоту настройки API.

5.3

PHP

Рабочая лошадка интернета (на нем работает WordPress и половина сайтов мира). Несмотря на стереотипы, современный PHP 8+ — это быстрый и строгий язык (особенно с фреймворком Laravel).

💡
Совет: Не пытайтесь выучить все языки сразу. Выберите один (например, Node.js или Python) и глубоко изучите его. Остальные языки потом будут учиться в разы легче.
Главная / §6 Базы данных

§6. Базы данных

Где и как хранить информацию

6.1

SQL (Реляционные БД)

PostgreSQL, MySQL, SQLite. Данные хранятся в строгих таблицах со связями (как в Excel). Идеально для финансов, пользователей, заказов, где важна целостность данных. Общение идет через язык запросов SQL.

SELECT name, email FROM users WHERE age > 18;
6.2

NoSQL (Нереляционные БД)

MongoDB, Redis. Данные хранятся в виде JSON-документов или ключ-значение. Гибкая структура, легко масштабируется. Отлично подходит для чатов, логов, кэша, где структура данных часто меняется.

6.3

ORM (Object-Relational Mapping)

Технология, которая позволяет работать с базой данных через объекты языка программирования, а не через сырые SQL-запросы. Например, в Node.js это Sequelize или Prisma, в Python — SQLAlchemy. Это ускоряет разработку и защищает от SQL-инъекций.

Главная / §7 API

§7. API и сетевые запросы

Как фронтенд общается с бэкендом

7.1

REST API

Архитектурный стиль, где сервер предоставляет данные по определенным URL (эндпоинтам) с использованием HTTP-методов: `GET` (получить), `POST` (создать), `PUT` (обновить), `DELETE` (удалить). Это стандарт де-факто для общения между сервисами.

7.2

JSON

Формат передачи данных, который понимают все языки. Выглядит как объект в JavaScript. Именно в таком формате сервер отдает данные, а фронтенд их рендерит. Он легче и удобнее, чем старый XML.

Главная / §8 UI/UX

§8. UI/UX Дизайн

Как сделать сайт не только красивым, но и удобным

8.1

UX (User Experience)

Это то, как пользователь взаимодействует с сайтом. Удобно ли ему найти кнопку? Понятна ли навигация? Хороший UX — это когда пользователь достигает цели быстро и без раздражения. Основные инструменты: логика, анализ конкурентов, юзабилити-тесты.

8.2

UI (User Interface)

Визуальная часть: цвета, шрифты, иконки, кнопки. Хороший UI строится по правилам: контрастность, единый стиль, отступы (воздух) и выравнивание по сетке.

8.3

Цвет и Типографика

Правило 60-30-10 (60% фон, 30% текст, 10% акцент). Шрифты должны быть читаемыми: не используйте больше 2-3 семейств шрифтов на одном сайте. Межстрочный интервал (line-height) должен быть не меньше 1.5 для комфортного чтения.

Главная / §9 Figma

§9. Figma и прототипирование

Главный инструмент современного дизайнера

9.1

Что такое Figma?

Это облачный редактор для создания интерфейсов. В нем дизайнеры рисуют макеты сайтов и мобильных приложений. Главная фишка — работа в команде в реальном времени (как в Google Docs).

9.2

Auto Layout

Это аналог Flexbox в Figma. Позволяет создавать адаптивные кнопки и карточки, которые меняют размер в зависимости от текста внутри. Обязательно к изучению для тех, кто делает дизайн, который потом пойдет в верстку.

Главная / §10 Адаптивность

§10. Адаптивность и медиазапросы

Сайт должен быть удобным на любом экране

10.1

Mobile First

Современный подход к верстке: сначала рисуем и верстаем для мобильного телефона (где меньше всего места), а потом расширяем для планшетов и ПК. Это гарантирует, что на телефоне сайт не сломается.

10.2

Медиазапросы

В CSS используются `@media` для применения разных стилей при разной ширине экрана. Это позволяет скрывать или перестраивать блоки под размер экрана.

/* Для экранов от 768px (планшеты) */
@media (min-width: 768px) {
    .container { display: flex; }
}
Главная / §11 DevOps

§11. DevOps и CI/CD

Как доставлять код на сервер без боли

11.1

Git и GitHub

Система контроля версий (Git) — это святое. Она позволяет сохранять историю изменений кода и работать в команде. GitHub/GitLab — это облачные хранилища для ваших репозиториев.

11.2

CI/CD

CI (Continuous Integration) — автоматическая проверка кода (тесты, линтеры) при каждом коммите. CD (Continuous Deployment) — автоматическая выгрузка кода на сервер после успешных тестов. Это избавляет от ручного копирования файлов по FTP.

Главная / §12 Хостинг

§12. Хостинг и домены

Где живет ваш сайт

12.1

Виды хостинга

  • Shared (Виртуальный): дешево, но ресурсы делятся с другими сайтами.
  • VPS/VDS: выделенный виртуальный сервер. Вы сами настраиваете окружение (Linux, Nginx). Идеально для коммерческих проектов.
  • Serverless (Vercel, Netlify): для фронтенда. Загружаете код, и он автоматически раздается по CDN.
12.2

SSL-сертификаты

Замок в адресной строке (HTTPS). Без него браузеры пишут «Сайт небезопасен». Сейчас можно получить бесплатный сертификат через Let's Encrypt.

Главная / §13 Безопасность

§13. Безопасность веб-приложений

Как защитить данные пользователей

13.1

SQL-инъекции

Злоумышленник может ввести SQL-код в форму входа и получить доступ к базе. Защита: использование подготовленных выражений (Prepared Statements) и ORM.

13.2

XSS (Cross-Site Scripting)

Внедрение вредоносного JS-кода на страницу. Защита: экранирование HTML-тегов при выводе пользовательских данных и использование Content Security Policy (CSP).
